# Расхождение API-документации и стенда

## Заказ создаётся без Authorization

Тест: `tests/test_orders.py::TestOrders::test_order_without_authorization`.

Источник: предоставленный PDF
https://code.s3.yandex.net/qa-automation-engineer/python-full/diploma/Api-Stellar_Burgers.pdf
В разделе авторизации написано, что заказы доступны только авторизованным пользователям.
Сам endpoint создания заказа описан раньше; явный статус для анонимного POST там не указан.
В тесте выбран 401 как ожидаемое отклонение запроса без авторизации.

Шаги:
1. GET /api/ingredients, выбрать реальные хеши булочки и начинки.
2. POST /api/orders, тело {"ingredients": [bun_id, filling_id, bun_id]}.
3. Не передавать заголовок Authorization.

Ожидание по правилу авторизации: заказ не создан (в тесте HTTP 401, success=false).
Фактически при подготовке: HTTP 200,
`{"success":true,"name":"Краторный минеральный бургер","order":{"number":6419}}`.

Перед сдачей стоит уточнить у наставника: требуется ли в этом задании зафиксировать
фактический контракт анонимного POST (200) либо проверить запрет из PDF.
Не менять assert на `status_code in [200, 401]`: это перестанет проверять требование.
Если наставник подтвердит 200 как контракт API, изменить название и ожидания этого одного теста,
проверяя также success и положительный номер заказа. Это осознанное уточнение требований.

Для неверного хеша PDF прямо требует 500; тест именно это проверяет,
не считает 500 автоматически дефектом теста и не требует JSON у HTML-ошибки сервера.
